# ADR-001 Tarifa por tipo de vehículo: Strategy en vez de switch

**Contexto.** El parqueo cobra por hora segun el tipo de vehiculo (auto, moto, residente). La primera version de GestorDeEstadias.RegistrarSalida() resolvia esto con un switch sobre el tipo, lo que obligaba a modificar esa misma clase cada vez que aparecia un tipo de vehiculo nuevo, una violacion de OCP (detallada en detecciones.md). El catalogo de tipos no esta cerrado: El edificio podria sumar "visitante" o "vehiculo de carga" en cualquier momento.

**Decision.** Se define la interfaz IEstrategiaDeTarifa con el método CalcularTarifaPorHora(), y una clase concreta por cada tipo de vehiculo (TarifaAuto, TarifaMoto, TarifaResidente). GestorDeEstadias.RegistrarSalida() recibe la estrategia ya elegida por parametro, en vez de decidir ella misma que tarifa aplicar.

**Alternativas consideradas.** Se evaluo **Factory Method** para centralizar la creación de la tarifa correcta segun el tipo de vehiculo — pero el problema aqui no es decidir que objeto crear, sino que cálculo ejecutar sobre una Estadia que ya existe: es un problema de comportamiento, no de creacion. Agregar una fabrica hubiera sumado una capa que este caso todavia no necesita. Tambien se considero dejar el switch como estaba, aceptando el riesgo de tener que modificar GestorDeEstadias cada vez que aparezca un tipo de vehculo nuevo, quedo descartada porque el propio enunciado anticipa que el catalogo de tipos puede crecer, y esa es justo la señal de que conviene resolverlo ahora.

**Consecuencias.** Se gana que un tipo de vehiculo nuevo se resuelve con una clase nueva que implementa IEstrategiaDeTarifa, sin tocar GestorDeEstadias. Se paga una interfaz y una clase más por cada tipo, en vez de un solo switch compacto.
